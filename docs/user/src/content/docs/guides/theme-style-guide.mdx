---
title: Theme style guide
---

The theme style guide lists the design values a theme declares, such as its
colors and font stacks. Site builders change them in the Brand Kit, preview
the changes, and publish them from Review changes. The theme's CSS, its
components, and Code Components then use the new values.

The style guide is experimental. It needs Drupal core 11.5 or later, which
provides the design tokens API it is built on.

## Declare design values in a theme

A theme declares its design values in `{theme}.tokens.yml`, in the Design
Tokens Community Group (DTCG) format. Groups become sections of the style
guide, and `$description` becomes help text.

```yaml
color:
  $type: color
  $description: 'Brand colors'
  semantic:
    primary:
      $value: '#0055aa'
font:
  heading:
    $type: fontFamily
    $value: [Inter, sans-serif]
spacing:
  $type: dimension
  sm:
    $value: { value: 8, unit: px }
```

Each value is a CSS variable named after its path: `color.semantic.primary`
is `--color-semantic-primary`. Set the same variables in the theme's CSS, so
the theme has its defaults when the style guide is off:

```css
:root {
  --color-semantic-primary: #0055aa;
}
```

The style guide lists values of the types `color`, `fontFamily`,
`fontWeight`, `dimension`, `number`, and `typography`, from the default theme,
its base themes, and enabled modules.

- Declare literal values. Aliases such as `{color.palette.blue}` are not
  supported yet, and core drops those values.
- Declare all five typography properties: `fontFamily`, `fontSize`,
  `fontWeight`, `letterSpacing`, and `lineHeight`.
- Use lowercase paths. Canvas lists paths with uppercase letters, but cannot
  save new values for them.
- Write font family names as CSS identifiers, such as `Noto Sans JP` or
  `-apple-system`. Names that need quotes, such as `Font 3`, cannot be saved.
- Core merges `tokens.yml` files by their top-level key: when two themes or
  modules declare `color:`, only one of them is used.

## Turn on the style guide

1. Open the Brand Kit and select **Style guide**.
2. Select **Turn on**, and confirm.

This changes the live site at once: the Brand Kit stylesheet then loads after
the theme's CSS, so values set in Canvas, and site colors that use the same
CSS variables as the theme, win over the theme's defaults.

To turn it off, open the menu in the **Style guide** tab and select **Turn off
the theme style guide**. Changed values return to the theme's defaults, and
come back when it is turned on again.

## Change and publish values

Each type has its own editor:

- **Colors:** a color field.
- **Font stacks:** an ordered list of families.
- **Font weights:** a named weight, or a custom whole number from 1 to 1000.
  When the first family of a typography value is an uploaded Brand Kit font,
  weights without a file are marked: browsers imitate them.
- **Dimensions:** a number in px or rem. Switching the unit converts the
  number at 16px per rem.
- **Numbers:** a number field.
- **Typography:** the family, size, weight, and line height. Letter spacing is
  shown but cannot be changed yet, because core does not output it. The family
  can start from one of the theme's font stacks; it is a copy, and does not
  follow later changes to that stack.

Invalid input stays in its field with an error, and is not saved.

- Every change is a draft. The editor preview shows it at once. The live site
  changes only when the draft is published from **Review changes**, where
  drafts are listed under **Style guide**.
- **Reset to default** restores the theme's value, as a draft too.
- Discarding a draft in Review changes removes it.
- When a value was changed elsewhere after a draft was created, for example by
  a configuration import, publishing the draft fails with "Changed elsewhere
  since you edited it". Discard the draft, or make the change again.

Published values are configuration (`core.design_token.*`). When a site's
configuration is deployed from code, a deploy replaces them, unless that
configuration is ignored.

## Use design values

- Color props in the component form offer the theme colors under **Theme
  colors**. A picked theme color follows the value set in the style guide.
- In CSS, use the variable: `color: var(--color-semantic-primary)`. The menu
  of each value has **Copy CSS variable**.
- Typography values are `font` shorthands: `font: var(--type-heading)`. The
  shorthand has no letter spacing.
