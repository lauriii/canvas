---
title: APIs - Import maps
---

Canvas uses [import maps](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap) to resolve JavaScript module specifiers for Code Components. The import map is built on the backend and injected into the page as a `<script type="importmap">` tag.

Modules and themes can add, remove, or modify import map entries using the `hook_canvas_importmap_alter` hook.

## Usage

Implement `hook_canvas_importmap_alter()` in your module or theme:

```php
function my_module_canvas_importmap_alter(array &$import_maps): void {
  $module_path = \Drupal::service('extension.path.resolver')
    ->getPath('module', 'my_module');

  // Add a new package.
  $import_maps['imports']['my-library'] = \base_path() . $module_path . '/js/my-library.js';

  // Replace an existing global import with a custom build.
  $import_maps['imports']['clsx'] = \base_path() . $module_path . '/js/custom-clsx.js';
}
```

The `$import_maps` array follows the [import map spec](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap) structure:

- `imports` — Global import entries mapping specifiers to URLs.
- `scopes` — (optional) Scoped import entries. Within a given scope URL prefix, bare specifiers can resolve to different URLs than the global entries.

## Examples

### Adding a Tailwind CSS plugin

To make a Tailwind CSS plugin available for use with the `@plugin` directive in Global CSS, add it to the import map.

```php
function my_module_canvas_importmap_alter(array &$import_maps): void {
  $module_path = \Drupal::service('extension.path.resolver')
    ->getPath('module', 'my_module');

  // Register a Tailwind CSS plugin.
  $import_maps['imports']['@tailwindcss/forms'] = \base_path() . $module_path . '/js/tailwindcss-forms.js';
}
```

Then use the `@plugin` directive in your **Global CSS**:

```css
@plugin "@tailwindcss/forms";
```

## Use cases

- **Adding a Tailwind CSS plugin**: Register a Tailwind CSS plugin so it can be used with `@plugin` in Global CSS.
- **Replacing a built-in package**: Swap a bundled package (e.g., `clsx`) with a custom build.

## Providing JavaScript for Code Components: publish it on npm

If your module provides JavaScript that Code Components import (a hook, a client for your module's endpoints, a component library), publish it as an npm package and declare it in your module's info file, rather than serving a file through the import map:

```yaml
canvas:
  npm:
    '@acme/canvas-forms': 1.2.0
```

Declare the exact version your module was built against. If a module update requires its client package to move with it, mark the declaration as required and `canvas pull` sets that version in the project even where it had another, and re-adds the package if it was removed:

```yaml
canvas:
  npm:
    '@acme/canvas-forms':
      version: 1.3.0
      force: true
```

A project paired with the site (`@drupal-canvas/cli`, Workbench, or a headless frontend) installs the package from npm like any other dependency. `canvas pull` adds the packages the site's extensions declare to `package.json`, and `canvas push` bundles and uploads them, after which the in-browser Code Editor resolves them too. A headless frontend has no Drupal import map at runtime, so npm is the only path that reaches it.

Do not also serve a copy of the same package through `hook_canvas_importmap_alter()`. The hook runs after the pushed manifest, so the served copy would override the pushed bundle on the site and in the editor while the CLI project and Workbench use the npm copy, and the two can drift apart.

## Notes

- This hook is invoked for both modules and themes.
- This hook is similar to what is being worked on for Drupal core (`hook_importmap_alter`) in [#3398525](https://www.drupal.org/project/drupal/issues/3398525). When that lands and Canvas adopts it, the `hook_canvas_importmap_alter` will be deprecated in favor of the core hook.
