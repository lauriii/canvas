---
title: SDC components - Options from site data
---

A prop can offer options that come from the site instead of a fixed `enum`:
the terms of a vocabulary, articles, users, or the results of a view. Content
authors pick from the options as they are when they edit, so site builders add
options without changing the component.

Add `x-canvas-options` to a `string` or `integer` prop. Its `source` says where
the options come from; the other keys configure that source.

```yaml
props:
  type: object
  properties:
    category:
      type: string
      title: Category
      x-canvas-options:
        source: entity
        entity_type: taxonomy_term
        bundles: [tags]
```

The component receives the ID of the chosen option, such as the term ID `'5'`.
Fetch what else you need with that ID, for example from JSON:API.

## Sources

### `entity`

Offers entities of a type, optionally of some bundles. The options respect
access: content authors only see entities they can view. Taxonomy terms are
listed as a tree.

| Key | Required | Example |
| --- | --- | --- |
| `entity_type` | yes | `taxonomy_term`, `node`, `user`, `media`, `menu` |
| `bundles` | no | `[tags]`, `[article, page]` |

### `view`

Offers the results of a view's **Entity Reference** display. Site builders
choose which entities are offered, their order and their labels in the view.

| Key | Required | Example |
| --- | --- | --- |
| `view` | yes | `featured_articles` |
| `display` | yes | `entity_reference_1` |
| `arguments` | no | `['5']`, the values of the view's contextual filters |

```yaml
    featured:
      type: string
      title: Featured story
      x-canvas-options:
        source: view
        view: featured_articles
        display: entity_reference_1
```

### Your own source

Modules can add sources, for example for options from an external API. Add a
plugin in `src/Plugin/Canvas/OptionsSource` with the `#[OptionsSource]`
attribute that implements `OptionsSourceInterface`, and define the config schema
type `canvas.options_source.<plugin ID>` for its keys. See `EntityOptionsSource`
for an example.

## Rules

- A prop with options from site data must be optional, because the site may have
  no options to choose from. It cannot have `enum` as well.
- For multiple values, put `x-canvas-options` in `items`:

  ```yaml
      topics:
        type: array
        title: Topics
        items:
          type: string
          x-canvas-options:
            source: entity
            entity_type: taxonomy_term
            bundles: [tags]
  ```

- Canvas validates the source when it discovers the component. An unknown
  source, entity type, bundle or view makes the component unavailable, with
  the reason in the component list.
- If an option is deleted later, pages that use it keep its ID. Handle IDs
  that no longer exist in the component.

Code components get the same sources from the **List: from site** prop type in
the code editor.
